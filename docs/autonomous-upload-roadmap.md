## 3. 用户实际要什么

任务单位是同一目录、同一剧的文件批次。系统自动扫描视频、识别集号、提取资料、核对历史，并复用同一可见浏览器连续处理。平台支持多选时，一次导入本批全部未处理视频；否则由 Agent 发现平台允许的导入方式，保留单文件幂等状态。

用户要的能力闭环是：

> 自动采集页面 → 理解当前状态 → 动态完成任务 → 记录成功证据 → 自动生成参数化工具 → 后续低成本复用 → 失效时自动修复并更新工具。

换平台时可以配置网址、账号和业务目标，页面步骤与字段对应关系由系统探索获得。业务规则不同，所需事实与授权也可能不同，不能声称任何平台都零配置或首次必成功。

用户不接受将“固定 Python 页面步骤 + AI 定位兜底 + 人工持续补选择器”作为最终方案。Playwright、Midscene 等可以保留为执行底座，架构改变发生在规划、学习和工具生成层。

## 5. 目标架构

```text
整剧业务任务
  ↓
任务调度与持久状态：读取断点、明确本批尚未完成的目标
  ↓
工具检索：平台、账号、任务意图、页面特征是否适用
  ├─ 有适用工具 → 执行 → 核实实际结果 → 记账并继续
  └─ 无工具/工具失效 → 观察 → 规划 → 动作 → 核实 → 再观察
                                          ↓
                                 记录成功步骤与证据
                                          ↓
                           参数化、验证、生成候选工具版本
                                          ↓
                             注册并在后续任务中检验复用
```

固定的是通用观察与验证循环，不固定“哪个平台第几步点哪个按钮”。

| 层 | 职责 | 实施原则 |
| --- | --- | --- |
| 业务与资料 | 整剧扫描、事实来源、元数据校验、去重、审核对账 | 复用现有能力，平台事实不由模型猜测 |
| 通用浏览器运行时 | 当前标签页、DOM、可访问性、截图、frame、弹窗、文件导入与等待 | 执行标准动作并回读，不预写平台页面顺序 |
| Agent 规划 | 根据任务和当前证据决定下一步或恢复策略 | 返回结构化动作，不只回答元素在哪 |
| 轨迹记录与工具生成 | 参数化成功步骤，提取适用条件、结果规则与恢复方式 | 先生成受限 JSON/YAML 流程，再考虑编译代码 |
| 工具库与调度 | 版本、检索、适用性、可信状态、失效与回退 | 首次成功为候选，后续不同输入验证后再升级 |

第一版用进程内工具注册、本地文件和 SQLite 即可。MCP 用于将来向其他 Agent 暴露工具；向量库、多 Agent、复杂编排框架都不是首个闭环的前提。

## 6. 自动生成的工具应保存什么

建议按“查询作品、读取集数、填写整剧资料、准备卡片、导入视频、核对结果、提交审核、检查审核”等能力拆分。不要只保存一条只能从首页执行的长录制脚本。

每份工具至少包含：

- 工具 ID、版本、平台、适用页面特征与账号作用域。
- 输入与输出 schema：剧集资料、真实集号、扫描白名单内的文件、实际结果 ID。
- 执行前条件、语义定位策略、备选定位、frame 与弹窗处理。
- 参数化动作、成功与失败判断、结果提取规则。
- 模型、耗时、tokens、恢复次数及关联的成功证据。
- 状态：`candidate`、`verified`、`invalid`；失败后修复为新版本，保留可回退版本。

例如工具 `添加单集卡片(数量)` 要验证卡片实际增加；只记录“点击成功”不合格。剧名、数量、文件路径是参数，不写死用户某次输入。坐标与临时 DOM ref 可作当次诊断，不能当永久工具身份。

只缓存操作方法。去重清单、上传结果、审核状态、当前授权等需要实时核实。浏览器凭据与秘密不写进工具模板。

生成阶段从成功轨迹中筛掉无效探索，建立清晰前后置条件；恢复后产生的“剩余步骤”不能冒充从初始页面可执行的完整流程。只读和可逆步骤可以重放验证；上传、保存或提交等有副作用的动作不能为了验收工具再次执行。

## 7. 恢复、幂等与“不阻塞”的定义

| 场景 | 行为 |
| --- | --- |
| 元素、frame、弹窗或页面路径变化 | 自动重新观察和规划，修复失效步骤，控制恢复次数与重复动作 |
| 单个批次恢复失败 | 保存证据和断点，挂起本批，继续其他可运行批次；按批汇报，避免逐集刷相同错误 |
| 模型或浏览器暂时不可用 | 分类记录；已有确定性工具仅在可安全执行时继续，其余任务保留，不反复付费重发 |
| 缺资料 | 自动找关联来源、提取和校验；仍缺则单剧记待补资料，继续其他任务，不要求用户逐字段录入 |
| 登录、验证码、法律协议或新的授权 | 保留需要用户操作的状态，暂停受影响操作；不绕过平台或替用户表态 |
| 上传/提交结果不明 | 先只读对账，不整批重放，不把“没有看到成功”推断成“尚未执行” |

任务检查点不等于平台副作用恰好执行一次。文件选择和提交前保存意图，结果按 SHA-256、平台、账号及实际作品/集数关联；确认后才能推进状态。原集号不能静默改号，平台标题别名和历史 ID 冲突要先核实。

用户已授权用其配置的第三方 deepseek-flash 处理当前快手截图和 DOM 进行测试；不把该范围扩大为允许发送无关秘密、切换供应商、接受法律协议或变更正式提交模式。

## 8. 分阶段实施与通过条件

### P0：隔离验证引擎可用性（下一步）

建议实验位置为正式项目下 `experiments/agent-learning/`；这是拟定目录，尚未创建。现有正式入口不变。

先锁定 Skyvern 的实际版本/提交，核对自托管版本是否具备所需 Adaptive Caching，而非仅依据云产品宣传。验证：

1. 可见本机 Chrome、当前登录会话和同一任务标签页能否接入；避免两个引擎同时操控同一页。
2. 当前 deepseek-flash 网关在该引擎下的视觉、结构化动作、长请求和错误反馈是否可用；不因不兼容而擅自换模型。
3. 本机文件白名单、视频多选、长上传等待、完成回执读取能否实现。
4. 成功步骤是否确实自动生成脚本，后续是否命中，失效是否交回 AI；收集实际文件和日志，不能只凭报告截图认定通过。

输出 `compatibility-report`：逐项写通过/失败/未测、证据、复现步骤与剩余问题。若关键能力缺失，做明确技术取舍；备用路线是给现有 Midscene 增加轨迹学习和工具库，不继续逐个平台手补页面步骤。

### P1：首次完成单视频与自动产出工具

选择身份明确、资料有来源、平台未上传的样本。不能把当前历史冲突的英文第3～6集作为唯一引擎验收样本。

Agent 从业务目标自主探索，记录状态、动作、结果与实际模型用量，生成候选工具。可先在本地模拟页验证整个生成机制，再做真实平台测试；两者证据分别标记。模拟停在最终提交之前，只能证明已验证的准备阶段，不能称为完整发布工具。

通过条件：原型由任务驱动、无需人工新增页面选择器，实际结果可核实，工具确由本次轨迹自动生成。

### P2：不同输入复用与成本对比

使用另一条合格视频或另一批资料。自动检索工具、绑定新参数、执行并核实。对比冷启动与复用的模型请求数、tokens、耗时、成功动作、恢复次数及工具命中情况。

通过条件：无需人工修改剧名、路径、集号或选择器；不混用旧结果；确实减少不必要模型调用。不要预先承诺固定节省比例。

### P3：页面变化与自动修复

在可控测试页改变按钮文字、容器、iframe 或增加普通弹窗。验证工具失效后 Agent 接管、保留已完成状态、修复局部流程并注册新版本。真实平台变化只做授权范围内验证。

通过条件：无需开发者改页面代码即可恢复，恢复预算耗尽时可挂起本批并继续其他批次，不无限点击、不重复上传。

### P4：第二平台与正式接入

提供第二平台入口、目标账号、业务目标与资料。验证系统可探索并生成平台工具，无需新增手写页面工作流。不同平台必填资料仍按真实来源核实。

前述阶段通过后，才增加新的可选执行入口并接入现有调度、资料、去重与账本。保留 Midscene/Stagehand/Browser Use 和旧逐集/批量路径，明确回退开关；仅当原型入口实际存在时才在 README 添加运行命令。
