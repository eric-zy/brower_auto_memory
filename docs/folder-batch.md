# 按文件夹一次批量导入

Midscene 的默认上传模式改为 `folder`。运行入口不变：

```powershell
cd E:\workSpace\brower-agent-test
python main.py
```

只处理某个目录：

```powershell
python main.py --directory "E:\upload_test\剧集目录" --max-jobs 0
```

同一直接父目录、同一剧名及版权身份的待处理视频合成一个批次，按真实集号排序。不同目录或不同剧不混合；子目录各自成批。SHA-256/平台/账号去重、资料校验、当前模拟模式与旧账本保留。封面采用第一个待处理视频的已校验封面，逐集生成的缩略图不同不会因此拆批。公共事实或版权证明冲突时停止该批次，不覆盖资料。

批次流程：列表查重一次 → 已有作品核对整剧清单，明确查无作品则进入新建表单 → 建立并核验本批单集卡片 → 公共资料及证明准备一次 → 使用实际支持 `multiple` 的视频控件一次选择所有本批文件 → 逐个核对文件名、完成回执及平台集号 → 模拟模式保留草稿，正式模式只点击一次整批提交，并逐集读取真实结果。

不再在进入新建表单前写死“必须是第1集”。若本地只剩第3～6集，页面必须能核实并保留第3～6集：有明确可写的集号字段时按原集号填写，没有时保留现场并说明平台卡片缺少哪些集号；不会创建空白前序集、复制已上传视频或静默改成第1～4集。文件名包含“第3集”不能单独证明上传到了平台第3集，完成回执需要同时核实文件名和平台集号。

选择文件前，所有成员先持久保存批次ID、文件哈希与选择意图。传输/提交结果不明时保持待核对，下一轮不整批重新导入。真实平台清单不完整、需要扫码、法律协议或授权确认时保留现场。已经完结的作品提前停止追加，未读取页的具体集数不会按总计数直接判定为已上传。

若需要原逐集流程：

```powershell
python main.py --upload-mode sequential
```

也可配置 `UPLOAD_MODE=sequential`。Stagehand、Browser Use 继续使用原逐集入口；新增的一次多文件导入仅接入 Midscene。`--max-jobs` 仍按视频数量限制，0为全部；指定非零值会截取本轮视频，不强制上传目录内其余文件。

本地测试使用拦截网站请求的 Chrome 页面和临时数据库，不消耗模型额度、不上传业务视频。测试通过不等于真实快手全链路验收。当前免费模型 HTTP402 及实际必填资料缺失仍需各自解决，程序不会自动换付费模型或关闭模拟模式。

## 合批预检与退出清理

批次资料在打开浏览器前预检。程序原先生成的 `《剧名》第N集。` 在模拟模式下属于占位文本，合批时统一为 `《剧名》。`；此处理只用于模拟表单，保留原单集资料、侧车文件和任务指纹，不能当作有剧情来源的正式简介。真实简介、备案、版权证明或模拟模式不一致时仍停止该批次，提示具体冲突字段和集号，并继续其他目录。正式模式的占位简介记录为待补资料。

人工操作判断使用实际异常和错误类型，日志阶段“检查登录”不会把普通资料错误变成登录异常。真正的扫码、验证、协议确认及权限问题仍停止整轮。

Browser Use 0.13 启动本项目拥有的 Chrome 时，兼容层保留其 asyncio Process 并将未使用的 stdout/stderr 管道改为 DEVNULL；退出及启动失败后等待回收该进程。该处理仅作用于本项目启动且携带 CDP 端口的 Chrome，Node 工作进程管道保持原样，不改第三方依赖文件或屏蔽 Python 警告。

添加单集入口也支持无 button/role 的可点击 div/span：依据实时点击属性或指针样式识别最小可操作文字节点，排除原生按钮的重复子节点、radio/checkbox/选项及禁用区域。点击前重新核实控件、frame和点击属性，不依赖固定CSS类。直接识别不唯一时才交给视觉定位，仍需验证实际卡片增加；这一恢复也按模型实际返回时间等待。协议、删除或提交等危险控件不会因此获得点击权限。

字段观察按外层完整 form-item 类名取得标签，避免误停在 form-item__content、丢失“单集标题”等文字。批量卡片复用同一观察结果，不再用另一套标签规则。弹窗识别包含标准 aria-modal、alertdialog 和原生 dialog；区域固定标为 dialog，明确添加数量后只确认一次，并等待弹窗关闭及卡片数量实际增加。出现其他协议弹窗仍停止。这里的数量表示新增多少集，不是设置起始集号；建立4张卡片不能证明可以把本地第3～6集导入为平台第3～6集。
